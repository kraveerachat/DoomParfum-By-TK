## Exact source and dependency implications

Existing `database.scento_etl.load_snapshot` is an operator-ETL loader and imports `local`. Its `tokens` strips tokens; `note_lists` suppresses General when layered notes exist; `build_plan` expands linked houses/materials; `mapping_proposal` proposes canonical UUIDs. These semantics do not implement the frozen preview. Do not import this ETL, invoke its SQL/import paths or modify it to make preview tests pass.

Existing `database.matching_input.read_profile(execute, profile_id)` consumes trusted SQL execution and canonical identity to produce selected/provenance-rich `ProfileInput`. Its `known_usable` states and reviewed timestamps are not raw unselected claims. It is not a preview input builder.

`matching_math.synthetic_m1.score_synthetic_notes_layered` and `matching_math.synthetic_b1.score_synthetic_b1` are implemented fixed-fixture typed functions. Their existence and input shape checks do not permit real records with fabricated fixture IDs or closure metadata. Keep both byte-preserved and uncalled. Exact math primitives are not needed by a five-record review adapter.

The compatible implementation is a small Python Standard Library module with explicit source/output inputs, immutable verified byte snapshots, strict CSV parsing, exact selector, raw evidence/state mapping, deterministic serialization and private publication. It has no import/call/dependency on `database/local.py`, ETL write paths, `database/matching_input.py`, either scorer, transport DTOs, UI routes or a live PostgreSQL/Docker service. AM-01 explicitly permits this independent lane after exact A/B/I approval.
