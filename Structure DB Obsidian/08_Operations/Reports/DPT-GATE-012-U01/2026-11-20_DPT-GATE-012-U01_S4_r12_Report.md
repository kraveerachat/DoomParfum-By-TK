## 4. One-time Owner setup checklist (Option A)

GitHub App creation, installation and repository rules are Owner administrative actions. The agent did not perform them. Do not paste keys or tokens into any chat.

**A. Protect `main` first** (Settings → Rules → Rulesets). Do this before installing any write-capable App.
1. Ruleset 1, "main protection": target the default branch; enforcement **Active**; bypass list **empty**. Rules:
   - Restrict deletions;
   - Block force pushes;
   - Require a pull request before merging, with 1 required approval, stale approvals dismissed, and approval of the most recent reviewable push required.
2. Ruleset 2, "main updates": the same target; rule **Restrict updates**; bypass list = the Owner (repository admin role) only. Write access alone lets an identity merge a PR whose rules are satisfied. With this ruleset, only a bypass actor can update `main`, so the App cannot merge even after an Owner approval.
3. Keep "Allow auto-merge" off. Do not add the App to any bypass list.
4. **Verify in the GitHub UI** that a merge by a non-bypass actor is refused (a test in §4.E). Until it is verified, treat "the agent cannot merge" as NOT VERIFIED.

**B. Create the App** (Owner account → Settings → Developer settings → GitHub Apps → New GitHub App).
- Name: for example `doomparfum-agent-publisher`. Webhook: **inactive**.
- Repository permissions: **Contents: Read and write**; **Pull requests: Read and write**; **Metadata: Read-only**. Every other permission: **No access**. That includes Administration, Workflows, Secrets, Actions, Environments, Checks and Pages.
- Account permissions: none. Installable: only on this account.

**C. Install the App** on **Only select repositories → `kraveerachat/DoomParfum-By-TK`**. Record the App ID and the installation ID; they are not secrets.

**D. Private key and isolation.**

Tokens are never written to files or logs. The token-minting step is new local tooling. It needs the Owner's approval before first use (AGENTS.md §5).
